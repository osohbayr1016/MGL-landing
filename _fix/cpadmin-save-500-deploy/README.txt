MGL E&C — CP Admin: мэдээ / төсөл хадгалахад гардаг "HTTP ERROR 500" засвар
==========================================================================

ШАЛТГААН
--------
2026-09-09-ний "site-update-deploy" багцаар cpadmin/pages/insert/post.sys.php
шинэчлэгдсэн. Тэр файл зураг хадгалах бүрдээ r2Store() / r2Remove()
функцийг дууддаг болсон (Cloudflare R2 руу зураг хуулах бэлтгэл).

Гэтэл тэр функцүүдийг тодорхойлдог cpadmin/r2.php-г ачаалдаг
cpadmin/config.php нь ямар ч багцад орж байгаагүй. Тиймээс сервер дээр:

  * зураггүй хадгалах        -> r2Store() дуудагдахгүй -> ХЭВИЙН ажиллана
  * шинэ зурагтай хадгалах   -> "Call to undefined function r2Store()"
                                -> PHP fatal -> хоосон "HTTP ERROR 500"

Мэдээний хувьд DB-д бичсэний ДАРАА зураг хадгалдаг тул мэдээ нь үүссэн
байдаг ч 500 гарна. Төслийн хувьд зургийг ЭХЛЭЭД хадгалдаг тул төсөл
огт үүсдэггүй. "Заримдаа ажиллаад заримдаа ажилладаггүй" нь яг үүнээс.

Баталгаажуулах (заавал биш): cPanel -> File Manager -> cpadmin/error_log
файлын сүүлийн мөрүүдэд дараах мөр байх ёстой:
  PHP Fatal error:  Uncaught Error: Call to undefined function r2Store()
  in /home/mglencmo/public_html/cpadmin/pages/insert/post.sys.php

--------------
public_html дотор ижил замаар нь дарж хуулна (overwrite), 5 файл:

  cpadmin/config.php                   — r2.php-г ачаалдаг мөр нэмэгдсэн
                                         (repo-д 09-03-наас байсан, серверт
                                         очоогүй байсан ГОЛ файл).
  cpadmin/r2.php                       — R2 функцүүд. ШИНЭ хувилбар: зургийг

                                         бөглөмөгц локал файлыг устгадаг байсан
                                         тул $gloCdnBase хоосон байхад сайт дээр
                                         зураг харагдахгүй болох эрсдэлтэй байв.
  cpadmin/r2.check.php                 — R2 холболтыг шалгах CLI скрипт

  cpadmin/pages/insert/post.sys.php    — r2Store() тодорхойлогдоогүй байвал
                                         өөрөө r2.php-г ачаална (давхар хамгаалалт:
                                         дараа дутуу хуулсан ч 500 болохгүй).
  cpadmin/user.sys.posts.php           — Хадгалах явцад ямар нэг fatal алдаа
                                         гарвал хоосон 500 биш, алдааны
                                         мэдээлэлтэй хуудас ("Хадгалах үед алдаа
                                         гарлаа" + Буцах линк) харуулж,
                                         cpadmin/error_log-д "CP Admin save
                                         failed [...]" мөр бичнэ. Ажлын

                                         алдаа буцаана.

const.php-д өөрчлөлт хийх ШААРДЛАГАГҮЙ. $gloR2* хоосон хэвээр байвал
зураг урьдын адил зөвхөн серверийн диск дээр (cpadmin/postpic/...) хадгалагдана.


ХУУЛСНЫ ДАРАА ШАЛГАХ
--------------------
1. CP Admin -> Мэдээ -> шинэ мэдээ, ЗУРАГТАЙ хадгална -> жагсаалт руу буцах ёстой.
2. CP Admin -> Төсөл -> шинэ төсөл, слайд ЗУРАГТАЙ хадгална -> жагсаалт руу буцах ёстой.
3. Хэрэв дахиад алдаа гарвал одоо хоосон 500 биш, шалтгаан нь бичсэн хуудас
   гарна — тэр текстийг хуулж өгнө үү.


R2 ШАЛГАХ (зураг R2 руу зөв хадгалагдаж байгаа эсэх)
----------------------------------------------------
r2.php-ийн гарын үсэг (AWS SigV4) нь AWS-ийн албан ёсны botocore
сантай яг ижил үр дүн өгдгийг локал дээр баталгаажуулсан. Сервер дээр
бодитоор шалгах дараалал:

1. cpadmin/const.php дотор 4 утгыг бөглөнө:
     $gloR2Account  = "<Cloudflare Account ID>";
     $gloR2Bucket   = "<bucket нэр>";
     $gloR2Key      = "<R2 API token Access Key ID>";
     $gloR2Secret   = "<R2 API token Secret Access Key>";
   ($gloCdnBase-ийг Worker ажиллах хүртэл ХООСОН орхино — зураг сервер
    дээрээ ч, R2 дээр ч давхар хадгалагдана, сайт хэвийн харагдана.)

2. cPanel -> Terminal дээр:
     php /home/mglencmo/public_html/cpadmin/r2.check.php
   Бүх мөр "OK" байвал холболт, эрх, bucket зөв. "FAIL" гарвал
   cpadmin/error_log дотор "R2 PUT ... failed: HTTP ..." мөрөнд
   шалтгаан нь бичигдэнэ (403 = түлхүүр/эрх буруу, 404 = bucket нэр буруу).

3. CP Admin-аас зурагтай мэдээ хадгалаад Cloudflare -> R2 -> bucket дотор
   image/news/<id>.jpg (мэдээ) эсвэл ceo/<нэр>.jpg (төсөл) үүссэн эсэхийг харна.

4. Worker-ийг (cloudflare/media-worker.js) байршуулж дууссаны дараа
   const.php-д $gloCdnBase = "https://<worker домэйн>"; гэж өгвөл сайт
   зургаа CDN-ээс уншиж, шинэ зургууд зөвхөн R2 дээр хадгалагдана.
